# LINUX INTERVIEW NOTES FOR CLOUD ENGINEER

1. LINUX BASICS

---

What is Linux?
Linux is an open-source operating system based on the Linux kernel. It is widely used in cloud computing, servers, DevOps, containers, and networking.

Why is Linux important for Cloud Engineers?

* Most cloud servers run Linux.
* AWS EC2 commonly uses Linux distributions.
* Docker containers commonly use Linux.
* DevOps tools such as Jenkins, Docker, Kubernetes and Ansible heavily use Linux.
* Linux provides powerful command-line and automation capabilities.

Common Linux distributions:

* Ubuntu
* Amazon Linux
* Red Hat Enterprise Linux (RHEL)
* CentOS / Rocky Linux / AlmaLinux
* Debian
* Fedora

4. FILE PERMISSIONS

---

Linux permissions are divided into:

User (u)
Group (g)
Others (o)

Example:

-rwxr-xr--

Meaning:

rwx -> User
r-x -> Group
r-- -> Others

r = read
w = write
x = execute

Numeric permissions:

r = 4
w = 2
x = 1

Examples:

chmod 755 script.sh

7 = rwx
5 = r-x
5 = r-x

chmod 644 file.txt

6 = rw-
4 = r--
4 = r--

Important commands:

chmod 755 file
Changes permissions.

chown user file
Changes file owner.

chgrp group file
Changes group ownership.

Interview Question:
Why is chmod 777 generally avoided?

Answer:
Because it gives read, write and execute permissions to everyone. This can create security risks. We should follow the principle of least privilege.

6. PROCESS MANAGEMENT

---

A process is a running instance of a program.

ps
Shows running processes.

ps aux
Shows detailed information about running processes.

top
Displays running processes and system resource usage.

htop
Interactive process monitoring tool.

pgrep process_name
Finds process IDs.

kill PID
Terminates a process.

kill -9 PID
Forcefully terminates a process.

jobs
Shows jobs running in the current shell.

bg
Moves a job to background.

fg
Brings a background job to foreground.

Interview Question:
What is the difference between kill and kill -9?

Answer:
kill normally sends SIGTERM, allowing the process to shut down gracefully.

kill -9 sends SIGKILL and immediately terminates the process.

7. SERVICES AND SYSTEMD

---

Modern Linux systems commonly use systemd to manage services.

systemctl status nginx
Checks service status.

systemctl start nginx
Starts the service.

systemctl stop nginx
Stops the service.

systemctl restart nginx
Restarts the service.

systemctl enable nginx
Starts nginx automatically during boot.

systemctl disable nginx
Prevents automatic startup.

journalctl
Displays systemd logs.

journalctl -u nginx
Shows logs for nginx.

Interview Question:
What would you check if NGINX is not working?

Answer:

1. Check service status.
2. Check NGINX configuration.
3. Check logs.
4. Check whether the required port is listening.
5. Check firewall/security-group rules.
6. Check whether another process is using the port.

Commands:

systemctl status nginx
nginx -t
journalctl -u nginx
ss -tulpn

---

Quickly searches for files using an indexed database.

Shows locations related to a command.

Searches text inside files.

9. DISK AND STORAGE

---

df -h
Shows filesystem disk usage.

du -sh directory
Shows directory size.

du -sh *
Shows sizes of files/directories.

lsblk
Shows block devices.

mount
Shows mounted filesystems.

mount /dev/sdb1 /mnt
Mounts a filesystem.

umount /mnt
Unmounts a filesystem.

Interview Question:
What would you do if a Linux server's disk is full?

Answer:

1. Check disk usage using df -h.

2. Find large directories using du.

3. Check /var/log.

4. Remove unnecessary files safely.

5. Rotate/compress logs if required.

6. Check application-generated files.

7. Increase disk size if necessary.

8. MEMORY AND CPU

Interview Question:
Server CPU is 100%. What will you do?

Answer:

1. Run top.

2. Identify the process consuming CPU.

3. Check application logs.

4. Determine whether the load is expected.

5. Investigate runaway processes.

6. Restart the application only if appropriate.

7. Check whether scaling is required.

13. SSH

---

SSH means Secure Shell.

It is used to securely connect to remote Linux servers.

Basic command:

ssh username@server_ip

AWS example:

ssh -i mykey.pem ubuntu@PUBLIC_IP

Important:

chmod 400 mykey.pem

This restricts access to the private key.

Common SSH troubleshooting:

* Check server IP.
* Check SSH service.
* Check port 22.
* Check firewall.
* Check AWS Security Group.
* Check username.
* Check private-key permissions.

14. LINUX FIREWALL

---

Ubuntu commonly uses UFW.

ufw status
Shows firewall status.

ufw allow 22
Allows SSH.

ufw allow 80
Allows HTTP.

ufw allow 443
Allows HTTPS.

ufw deny 8080
Blocks port 8080.

Important:
In AWS, Linux firewall rules and AWS Security Groups are different layers.

Security Group -> AWS network-level access control
UFW -> Host-level firewall

20. PROCESS VS THREAD

---

Process:

* Independent running program.
* Has its own memory space.
* More expensive to create.

Thread:

* Smaller execution unit inside a process.
* Threads share process memory.
* Usually cheaper than processes.

Interview Question:
Why is this relevant to Cloud Engineers?

Answer:
Understanding processes and threads helps with performance analysis, resource management and troubleshooting applications running on cloud servers.

21. HARD LINK VS SOFT LINK

---

Soft link:

ln -s original.txt link.txt

A soft link points to another file path.

Hard link:

ln original.txt hardlink.txt

A hard link points to the same inode/data.

Important difference:

Soft link:

* Has a separate inode.
* Can point to directories.
* Can cross filesystems.
* Breaks if the target path is removed.

Hard link:

* Shares the same inode.
* Normally cannot be used for directories.
* Cannot cross filesystems.

22. INODE

---

An inode stores metadata about a file.

It contains information such as:

* File permissions
* Owner
* Group
* File size
* Timestamps
* Location of data blocks

It does not normally store the filename itself.

Command:

ls -i

Shows inode numbers.

Interview Question:
Can a server have free disk space but still fail to create files?

Answer:
Yes. The filesystem may have run out of inodes.

Check using:

df -i

30. INTERVIEW APPROACH

---

Do not just memorize commands.

For every command, understand:

1. What does it do?
2. Why do we use it?
3. What problem does it solve?
4. What output does it give?
5. What would you do if it shows an error?

Example:

Question:
How do you troubleshoot high disk usage?

Strong answer:

"First I check the filesystem using df -h. Then I identify which directories are consuming the most space using du. I check /var/log and application-generated files, clean unnecessary data safely, and verify the disk usage again. If the workload genuinely requires more capacity, I would expand the storage."

This type of answer demonstrates practical Cloud Engineer knowledge instead of only memorizing commands.
